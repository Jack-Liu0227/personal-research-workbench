- 每个项目区块（包括日历、任务、文献、笔记、资源）必须提供删除按钮。

## V2 聚合与权威边界

- Project Space 展示的是 Workspace Service 的只读聚合快照：项目进度、任务、Paper、矩阵、日历（含只读虚拟投影）、Obsidian `note_index`、ResourceLink 和知识库元数据。
- Prompt、模板、每日推送、综述正文和矩阵 Markdown 快照仍由 Vault 文件管理；SQLite 只保存结构化事实、索引、关联、fingerprint 和运行状态，不能复制正文成为第二权威源。
- 子资源写入必须复用任务、Paper、日历、Obsidian layout/note 和外部连接命令；项目归档不自动移动或删除 Vault 文件。

## Obsidian 项目空间目录约定

选择 Vault 后不创建项目子目录，也不添加数字前缀。根级默认分类为 `每日文献推送`、`文献矩阵`、`文献综述`、`写作模板`、`提示词库`、`AnythingLLM` 和 `LLMWiki`；用户可任意新增、重命名或删除根级分类。项目隔离统一通过 Markdown frontmatter 的 `projectId`、`workbench_project_id`、`labels/tags: [project:<id>]` 实现，同一文件允许关联多个项目；没有标签的文件归入未分类。

## 页面目标

以研究项目为上下文聚合任务、文献、文献矩阵、笔记、日历、知识库、资源和活动，是工作台的核心业务页面。

## 页面结构

### 项目顶部区

- 项目名称、状态、研究方向、时间范围、进度和标签。
- 项目切换、收藏、归档、导出、派发 AI Job 和复制 MCP Resource 地址。

### 项目内页面

- 总览：目标、阶段、近期活动和下一步。
- 任务：项目任务看板、列表和时间线。
- 文献：项目论文、待读、精读和引用状态。
- 文献矩阵：结构化比较论文。
- 笔记：Obsidian 笔记与工作台草稿。
- 知识库：AnythingLLM 索引状态与 LLMWiki 页面。
- 日历：里程碑、任务、实验和投稿计划。
- 资源：数据集、代码、网页、文件和外部链接。
- 活动：资源、AI Job、MCP 调用和外部同步记录。
- 自动化：项目简报、保存检索、Wiki 摄取、周报与投递规则。

## 文献矩阵

- 固定列：论文、作者、年份、期刊、研究问题、方法、数据集、关键发现、局限、研究空白、我的笔记、标签、Zotero、Obsidian。
- 自定义列类型：文本、数字、单选、多选、日期、布尔、URL。
- 支持列宽、固定列、排序、筛选、分组、虚拟滚动、导出。
- AI SDK 可生成字段候选，用户逐行确认后写入。
- 外部 Agent 可通过 MCP 查询或填写授权列。

## 知识库

- AnythingLLM：显示 Workspace 映射、文档索引状态和最近查询。
- LLMWiki：显示 Wiki 目录、页面、来源谱系、健康检查和最近摄取。
- 原始论文、PDF 与笔记不重复存储。

## 后续设计：项目自动化（未启用）

以下规则是后续阶段设计；当前版本只展示已落库的项目、任务、Paper、矩阵和连接元数据。

- 每个项目可绑定一个默认现成 Agent、一个 AnythingLLM Workspace、一个 LLMWiki 目录和若干投递目标。
- 自动化列表显示规则、触发器、查询范围、Agent、下次运行、最近结果、连续失败和启用状态。
- 默认模板：每日项目简报、每周周报、保存检索新增论文、Zotero 新增摘要、Wiki 健康检查。
- 自动化结果进入项目活动流和简报收件箱；结构化结果可以转为任务、矩阵字段草稿或 Wiki 页面候选。

## 后续设计：MCP 范围（受控读写）

- Project 作为组合 Resource，返回项目元数据和资源链接，不默认返回全部 PDF 正文。
- Tools：项目读取/更新、加入论文、填写矩阵、建立关系、派发 Wiki 摄取或 AI Job。
- 外部 Agent 的写入均记录到项目活动流。

## 2026-08-30 需求增量：统一记录与知识引擎目录

- 项目空间只聚合权威任务、论文、矩阵、日历、资源和 Obsidian 索引，不创建第二套副本。
- 项目初始化布局新增 `AnythingLLM` 与 `LLMWiki` 两个一级知识目录；所有目录创建都必须经过预览、冲突选择和明确确认。
- 项目筛选通过 projectId/frontmatter label 解析，未分类文件保留在 Vault 根级或 Inbox，不强行归入项目。

## 2026-08-30 最终基线：标签聚合

- 工作台按 `projectId` 聚合统一任务、Paper、文献矩阵、综述、日历事件、Obsidian note 和知识引擎索引，不创建项目专属 Vault 子目录或重复缓存。
- Obsidian 文件的项目归属只来自 frontmatter `projectId`/`labels`；根级分类目录仅表示内容类型。未分类内容仍可在项目空间的“未分类”筛选中访问。
- 任何聚合卡片的打开、编辑、删除和资源管理器查看都回到权威记录或经过安全校验的 Vault-relative 文件路径。
