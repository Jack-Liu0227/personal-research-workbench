# 日历

## 2026-09-08 最新需求与验收（以本节为准）

- 项目空间中的日历区块必须提供删除按钮；删除真实事件前显示影响范围并二次确认。
- 删除通过 CalendarMarker/事件命令执行，必须携带 revision/CAS；失败时保留原记录并显示失败原因。
- 任务和项目在日历中的投影仍为只读，删除投影只能跳转到来源实体。

状态：PARTIAL。需要补齐项目空间入口、确认对话框和删除审计。

> 文档状态（2026-08-30）：本文件是日历模块的唯一计划源。共享 SQLite、任务归档/硬删除和 Wave 1 验收约束已合并到本文件；旧执行计划不再单独维护。

## V2 数据一致性与删除语义

- 显式日历事件、任务截止日期和项目里程碑来自同一个 Workspace Service/SQLite 读快照；日历不保存第二份任务或项目记录。
- `task:<id>` 与 `project:<id>` 是只读虚拟投影，只能打开来源检查器，不能在日历中直接更新或删除；修改截止日期必须调用任务/项目命令。
- 任务硬删除在同一数据库事务中清理本地关联日历记录、ResourceLink/ExternalLink，并使日历查询缓存失效；外部 Zotero/Obsidian 资源不被删除。
- 创建、拖动、编辑和删除显式事件后，任务、项目和仪表盘查询必须同步失效；失败时保留原事件，不显示整体成功。

## 全区域右键标记与删除（新增需求）

- 月视图日期格、周/日视图时间槽、全天区域、事件卡片和议程行都必须提供右键菜单，并提供菜单键/`Shift+F10` 等价操作；不能只给已有事件绑定右键。
- 空白日期/时间区域的“添加标记”会带入命中的日期、时间、当前项目上下文和用户时区；用户可选择标记类型（笔记、提醒、里程碑、每日推送、阅读、截止）并填写标题、颜色和备注。
- 已有标记的面板行支持编辑、删除和右键删除；删除必须带 revision/确认并在数据库提交后才从所有视图消失。取消或冲突不改变原标记。
- 任务/项目截止等只读虚拟投影只能“打开来源”，不能添加覆盖标记或直接删除；要修改来源必须回到任务/项目命令。
- 标记不是 Renderer 临时状态：作为统一 SQLite 中的 `CalendarMarker` 保存，包含稳定 ID、日期/时间、类型、项目/任务/Paper 关联、颜色和 revision。日历主视图与标记面板复用同一记录；任务硬删除会在同一事务中清理其关联标记。
- 新增表/字段必须由 Architecture & Contracts 与 Database 冻结 migration 后再实现；在此之前不得用 localStorage、演示数据或第二套标记数组替代。

## V2 验收状态

基础日历 CRUD、范围视图、任务/项目截止投影、revision 保护、月/周/日/议程空白区域右键入口已接入。持久化 `calendar_markers` migration、标记创建/编辑/删除面板和版本锁保存已接入；标记列表与日历使用同一 Workspace SQLite。仍未完成的发布门禁是重复规则、Windows 安装包 smoke、Zotero/Obsidian 真实外部验收和完整人工回归，未运行的命令不计为完成。

## 页面目标

统一呈现独立日程、任务日期、项目里程碑、阅读计划、实验计划和投稿节点，并支持时间视角的科研排期。

## 页面结构

### 顶部工具栏

- 月、周、日、议程、时间线视图。
- 今天、上一周期、下一周期。
- 项目、类型、状态和标签筛选。
- 新建日程、新建任务、导入任务日期。

### 日历主体

- 独立日程、带日期任务、项目里程碑。
- 论文精读、实验、会议、投稿、返修和提醒。
- 不同项目与事件类型使用可配置颜色。
- 左侧可显示未排期任务，拖入日历后生成时间关系。

### 右侧检查器

- 标题、类型、项目、日期、持续时间、重复规则。
- 关联任务、论文、笔记和会议材料。
- 提醒、状态、标签、备注和活动记录。

## 关键操作

- 拖拽调整日期和持续时间。
- 从日程创建任务，从任务创建日历事件。
- 从论文创建阅读计划，从项目创建里程碑。
- 后续 AI SDK 可生成排期草稿，确认后批量写入。
- 外部 Agent 可通过 MCP 查询空闲时间、创建日程和重新排期。

## 后续设计：Agent 自动化（未启用）

以下自动化规则保留为后续阶段设计，当前版本不执行调度或 Agent 写入。

- 自动化规则在日历中显示为只读的“Agent 计划”标记，可查看下一次运行和最近结果。
- 每日 08:00 简报、每周一项目周报、保存检索追踪均使用用户时区和明确的错过触发策略。
- Agent 生成排期时先创建排期草稿，展示新增、移动、冲突和未排期项目，确认后通过 Command Service 提交。
- 外部 Agent 查询空闲时间只返回授权范围内的忙闲信息；读取事件标题与备注需要更高权限。

## 2026-08-30 需求增量：任务联动与统一事件源

- 任务截止时间通过 `CalendarEvent(id=task:<id>)` 投影到日历；任务创建、编辑、移动、归档和硬删除后，日历查询必须同步失效并立即反映结果。
- 日历不复制任务字段；任务标题、状态、项目和 dueAt 只从任务记录读取，日历只允许编辑独立日程或持久化 marker。
- 日历右键创建的事件/标记仍写入同一 Workspace SQLite，并保留来源 taskId/projectId/paperId 关联。
- 发布验收新增：在任务页设置带分钟的截止时间后，刷新或切换日历范围仍能看到同一条记录；删除任务后日历不残留。
- 日历 Inspector 的“打开任务/打开项目”通过受校验的 `workbench:open-source` 资源事件切换到权威页面；任务页接收资源焦点并打开对应 Inspector，不再停留在仅显示提示的假跳转。

## 2026-08-30 最终基线：日历是统一记录的投影

- 月/周/日网格、议程列表和每个日期单元格都支持右键创建标记或独立日程，也支持删除；操作写入统一 Workspace SQLite 并要求确认。
- 任务事件由 `task:<id>` 投影生成，标题、状态、项目、创建时间和截止时间永远从 `tasks` 表读取；任务删除、归档、移动或编辑后立即失效日历查询。
- 无 dueAt 的任务使用 createdAt 作为预览时间，默认显示到分钟；点击日历条目可跳转任务 Inspector，不能只显示脱离数据源的文本。
