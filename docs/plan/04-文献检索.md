# 文献检索

## 2026-09-08 最新需求与验收（以本节为准）

- `SEARCH / FREE SOURCES` 固定在顶部横向区域；结果区与 Inspector 采用可拖动分隔条，默认约 5:1。
- `INSPECTOR / PAPER` 仅支持左右折叠；分页提供上一页、下一页、页码、总数和每页数量，数据必须来自真实 `total/hasNext`。
- 单条或批量结果都支持通过 DOI/URL 匹配或创建 Zotero item；写入前预览确认，写入后逐条返回成功、跳过、冲突和失败。
- 搜索结果可加入 Zotero Collection，也可导出 BibTeX 供 Agent Runtime 使用；两者是独立动作。
- 影响因子只显示可靠来源及获取时间，缺失时显示“未提供”，禁止推测。

状态：PARTIAL。分页接入、DOI/URL 写入 UI、影响因子来源仍需完成真实服务验收。

> 文档状态（2026-08-29）：本文件是文献检索、批量操作和导入工作流的唯一计划源。新检索/清理/综述/矩阵/导出约束已合并；旧执行计划和 Vault 设计文档不再单独维护。

## V2 首版搜索与清理边界

- 首版已接入 Local、Crossref、OpenAlex、PubMed、arXiv、Semantic Scholar 和 scholarly 侧车的公开检索适配器；Google Scholar 侧车只在用户主动检索时逐页运行，遇到验证码或限流立即停止。任一来源网络失败只显示错误，不伪造搜索成功。
- 结果优先支持关键词、来源、年份、作者、排序、筛选、分页和去重；检索是主功能，单篇/批量导入是结果操作，不是暂存文献库。
- `SearchSession`/`SearchResult` 仅保存当前检索和批处理来源。用户可清空当前结果；清理在同一事务中删除 `search_results` 与 `search_sessions`，不删除已导入的 Paper、项目关系或 Zotero 记录。
- 选择身份使用 `source + sourceId`（去重后），批量操作先预览再确认，逐条返回成功、跳过、冲突和失败；外部 Zotero 写入不与 SQLite 事务混合，也不在后台无人值守执行。

## 文献工作流设计（后续分阶段）

- 每日推送按论文、新闻、专利、综合摘要分类，生成可追溯 Markdown 投影；当前版本只做手动搜索/预览/导入/导出，不启用后台调度或 AI 摘要。
- 文献综述使用 SQLite 关联 Paper/项目/版本，正文和证据卡片写入 Vault，并以 fingerprint 冲突保护；删除 Paper 不删除综述正文，只显示断链。
- 文献矩阵以 SQLite 行和列定义为事实源，可导出 Markdown/CSV；从 Markdown 回写必须显式预览版本与列冲突。
- RIS、BibTeX、CSV、JSON、Markdown 导出向导必须明确“生成文件”与“已导入 Zotero”的区别；默认写入用户选择的 Vault 根级分类或自定义导出目录，不自动创建带数字前缀的 `10-文献导出/`。

## V2 验收状态

Crossref/OpenAlex/本地/PubMed/arXiv/Semantic Scholar 检索、结果筛选排序、50 条分页、结果导入、清空当前 session、论文编辑和基础批量预览/确认已有代码证据；开放指标排序使用公开引用代理并明确不是期刊影响因子。Zotero 本地授权后的新条目 POST、既有条目 revision-checked PATCH、集合选择和导入回执已接入；真实 Zotero、Vault 和外部网络回归仍需在受控本机验收。

## 页面目标

以可真实探测的 Local、Crossref 和 OpenAlex 完成首版论文发现，并逐步接入 PubMed、arXiv、Semantic Scholar 与 Google Scholar；未可用来源只显示不可用或用户触发的外链，不伪造检索成功。

## 来源导航

- Google Scholar：默认来源与完整高级检索入口；通过用户触发、页数受限的 scholarly 侧车接入。
- PubMed：医学与生命科学检索、PMID、摘要。
- arXiv：预印本与 arXiv ID。
- Semantic Scholar：摘要、引用和主题信息。
- Crossref：DOI、ISSN 与出版元数据。
- OpenAlex：学术图谱、来源匹配与开放影响指标。
- 跨源检索：用户勾选来源后并行查询，保留来源记录。

## 搜索区

- 关键词、精确短语、作者、期刊、DOI。
- 年份范围、至少一个关键词、排除关键词、标题内检索。
- 包含专利、包含引用、保存检索和项目上下文。

## 结果区

- 标题、作者、期刊或会议、年份、摘要片段。
- 引用次数、来源、DOI、PMID、arXiv ID 和开放全文状态。
- OIM-2Y、指标年份、覆盖状态和来源。
- 操作：PDF、详情、引用、加入待读、加入项目、加入矩阵、导入 Zotero、创建任务。
- 分页按需加载，每页默认 50 条，访问页写入 SQLite。

## 排序与去重

- 相关性、最新、引用次数、年份和开放影响指标。
- 开放指标排序只作用于已加载结果并明确标注。
- 去重顺序：DOI、PMID、arXiv ID、规范化标题 + 第一作者 + 年份。
- 合并后保留字段来源、原始记录和匹配置信度。

### MOSAIC 集成边界

- 首期把 MOSAIC 当作可替换的检索 Worker，不嵌入其 Web UI。
- 每次调用传入来源、查询、筛选、最大结果数和输出 JSON；Sidecar stdout 只允许结构化结果，stderr 进入连接器日志。
- 工作台重新执行 DOI/PMID/arXiv ID/标题作者去重，并保存 MOSAIC 原始记录，避免第三方合并规则不可追溯。
- Scholar Connector 保持独立，不伪装为 MOSAIC 来源。
- MOSAIC 提供 GPL-3.0-or-later、BSD-2-Clause、BSD-3-Clause、MIT 多许可证选择；实际发布前在依赖清单中固定所选许可证和版本。

## 2026-08-30 执行补充（当前有效约定）

- “导入 Zotero”批量动作先把选中的检索结果幂等导入本地 `Paper`，再调用 Paper→Zotero 预览；确认后，具备写能力时创建/更新真实 Zotero 条目并登记 ExternalLink；权限不足或写入失败按逐条失败回执返回。未加载完的“全选结果”不会伪造批量成功。
- 检索页的 staging 导入固定请求 Zotero Local API 写入；只读或未授权连接按逐条失败回执返回，保留失败项供重新预览和再次导入，不自动生成离线导入包。

- 右键检索结果仍提供单篇“导入当前项目”和“导入 Zotero（预览）”；批量选择使用同一套确认和结果回执。

## 2026-08-30 最终基线：检索优先、轻量待分类

- 文献检索页的唯一主任务是联网检索、筛选、排序和分页。默认并行调用可用的免费来源（Crossref、OpenAlex、PubMed、arXiv、Semantic Scholar、scholarly 等），Google Scholar 仅通过用户触发的受限侧车逐页请求，不绕过验证码或限流。

### 2026-08-30 实现校准

- 待分类会话列表提供当前会话清空、单条删除、可见会话全选和批量删除；所有删除请求都经 Workspace Service 事务执行，并在成功后刷新会话列表。
- Zotero 配置与集合选择位于检索结果工具条；当只读探测成功而写入未授权时，检索页直接提供“申请本地写入授权”，不会把未授权写入显示为成功。
- 选中结果先写入统一 SQLite `papers` 表并保留稳定 source/externalId/DOI，再按用户确认执行 Zotero 或项目关联；失败、跳过、冲突逐条显示，未运行的外部服务不标记成功。

## 2026-08-31 合同增量：持久化待分类记录

- `SearchSession`/`SearchResult` 继续只承担当前检索的可清理缓存语义；清空会话只删除缓存结果，不删除已经保存的待分类记录。
- 需要长期保留的结果通过独立的 `LiteratureStagingRecord` DTO 保存。该记录携带来源、稳定 `sourceId`、去重证据、可选来源会话和本地 `paperId` 投影，并有独立的 `revision`/时间戳。
- 工作台服务边界固定为严格 RPC：`literature.staging.page`、`literature.staging.save`、`literature.staging.delete`、`literature.staging.bulkDelete`。批量删除使用 ID 选择集和逐条 revision 锁，返回逐条 outcome，不把部分失败汇总为成功。
- 待分类导入 Zotero 使用独立的 `literature.stagingToZotero.preview` → `literature.stagingToZotero.execute` 确认对；外部写入仍需 capability probe 和用户确认，RIS/BibTeX handoff 不表示已导入。
- 输入校验、Zod 解析和远端响应映射均使用结构化、脱敏的字段级集成错误 envelope，禁止把原始响应、凭据、绝对路径或内容泄漏到 Renderer。

### 2026-09-09 分页与排序实现说明

- 搜索首屏按每页数量展示；远端续页使用服务层签发的 opaque cursor，访问下一页时才请求来源并将新结果追加到同一 SearchSession。总数在来源没有提供准确 total 时显示为当前已加载数量加号，不猜测未加载数量。
- 结果工具条提供年份筛选、年份升/降序、影响因子升/降序和公开引用指标升/降序。影响因子仅接受来源明确提供的数值；OpenAlex 的 `summary_stats.2yr_mean_citedness` 会显示为 `IF*`（公开 IF 风格指标，明确标注为非 JCR），Crossref 等只返回引用或来源元数据时继续显示“未提供”，避免把引用数冒充 JCR IF。
- Zotero 写入结果保留逐条失败回执；失败 staging 记录不自动删除，修复连接后可重新生成预览并再次确认写入。

- 检索页收敛为两个标签：`检索` 与 `待分类`。页面不再展示 `BATCH / EXPLICIT`、重复的 Zotero 浏览侧栏或把待分类伪装成 SearchSession 的第三个入口。
- 搜索结果默认从最近一次 `SearchSession` 和 `literature.resultsPage` 恢复；切换页面后仍可继续查看最近一次结果。每页请求 50 条，当前页提供标题/作者/期刊筛选和相关性、年份、影响因子、标题和公开引用指标排序。
- 每一行提供可见复选框、来源链接和 `+`。配置了 Zotero 时，`+` 会先持久化待分类记录并生成 Zotero 预览；未配置时只保存待分类，不伪造导入成功。批量按钮和右键菜单使用同一预览→明确确认→逐条回执流程。
- 结果详情默认折叠，仅在展开后显示 Zotero 风格的标题、作者、期刊/年份、摘要和 URL；不展示重复的连接探测或内部去重字段。
- 待分类是独立 `literature_staging` 表，可单条/多选删除，不受搜索会话清理影响。SQLite、Workspace Service、Main/Preload 和 Renderer 共用同一组版本化合同。
