- 时间筛选默认为 `createdAt`；工具栏提供一个按钮在“创建时间/截止时间（dueAt）”之间切换。

- 所有列和卡片按钮必须具备 title/aria-label/Tooltip。

## 目标调整：只保留“我的任务”，移除 FOCUS

- 左侧导航和任务路由不再提供 `FOCUS` 分组、Today/Upcoming/Overdue/Completed 等独立 Focus 页面；只保留一个“我的任务”入口。
- “我的任务”必须同时提供完整看板和列表视图（可继续提供时间线作为视图切换），并保留搜索、筛选、排序、拖拽、右键菜单、列内右键快速创建和键盘等价操作。
- 视图筛选（今天、即将到期、逾期、已完成）只能作为“我的任务”内部筛选或保存视图，不得重新生成导航菜单或第二套查询/删除逻辑。
- Todo 是我的随记/快速捕获，不要求关联项目：默认写入同一 `tasks` 表的 `projectId=null + status=inbox`；用户以后可以在 Inspector 中主动归属项目，但创建时不得强制选择项目，也不能写入 Obsidian 作为第二份记录。
- 当前 Shell 已移除独立 FOCUS 导航和 Focus 路由；指标卡统一跳转“我的任务”，时间/状态筛选保留在任务工作区内部扩展。

## V2 任务生命周期（已冻结）

- 普通“删除”只执行归档（持久化 `archived`/`archivedAt`）；归档视图中再次确认后才能硬删除。
- 硬删除必须携带 revision 与一次性确认上下文，只有数据库提交成功后才返回成功；同一事务清理本地日历投影、资源链接和外部链接记录，不触碰 Zotero 原库或 Obsidian 文件。
- 恢复只接受已归档任务，并按规则恢复到收件箱或项目默认列；任务不是第二个 Todo 实体，Inbox Todo 只是 `projectId=null + status=inbox`。
- 所有页面（看板、列表、日历、项目空间、仪表盘）查询同一任务记录，归档/恢复/硬删除后统一失效相关 query。

## 看板右键与快捷创建

- 每个可用状态列的标题和空白区域都支持右键创建，也支持 `Shift+F10`/键盘等价入口和列内 `+`。
- 创建对话框必须继承当前项目、目标列和状态；不能先创建演示任务再隐式移动。归档列和未同步占位列不得伪造成功。
- 卡片右键菜单与键盘菜单复用同一个 `ContextMenuTarget`，归档、恢复、硬删除都显示真实的影响范围和确认步骤。

## 页面目标

管理科研执行事项，并将任务与项目、论文、笔记、日程、Zotero 条目、AI Job 和外部 Agent 调用连接起来。

## 页面结构

### 顶部工具栏

- 看板、列表、时间线视图。
- 搜索、筛选、分组、排序和保存视图。
- 按项目、状态、优先级、截止日期和标签过滤。
- 新建任务与批量操作。

### 任务字段

- 标题、描述、状态、优先级、项目、截止日期。
- 标签、子任务、检查清单、预计工作量。
- 关联论文、Obsidian 笔记、Zotero 条目、日历事件。
- 来源：用户、页面操作、AI Job、MCP 客户端。
- 创建、更新、完成时间和活动记录。

### 状态

- 待整理、待开始、进行中、审阅中、已完成、已归档。

### 右侧检查器

- 修改状态、优先级、日期、项目和描述。
- 管理子任务、检查清单和关联资源。
- 展示关联 AI Job、MCP 调用来源和变更历史。

## 关键操作

- 拖拽卡片改变状态、顺序和项目。
- 从论文、笔记或检索结果创建任务并自动建立关联。
- 后续 AI SDK 可拆解任务、生成子任务和提取下一步动作。
- 外部 Agent 可通过 MCP 创建、更新、完成任务或派发 AI Job。

## 后续设计：Agent 自动化（未启用）

以下内容保留产品方向，但当前版本不执行 Agent、AI Job 或自动化规则。

- 每日简报可将“建议下一步”一键转为任务，并保留 `sourceArtifactId` 与来源 Agent。
- Agent 拆解任务生成子任务草稿，展示标题、预计工作量、依赖、日期和证据，用户确认后写入。
- 自动跟进规则可以在截止前生成风险提示、延期建议或周报素材，但写入状态与日期仍经过工具权限。
- 任务检查器显示 Agent Run、MCP 客户端、原始规则、幂等键和变更前后差异。

## 2026-08-30 需求增量：统一任务来源与真实看板交互

- 看板所有状态列（待整理、待开始、进行中、受阻、已完成、已归档）都必须可以右键或 `+` 创建；创建请求携带目标状态，不能先落到待开始再隐式移动。
- 卡片和列表右键同时提供“归档”和“直接删除”。直接删除仍显示不可撤销确认，并通过统一 Task Command、revision 和数据库事务执行；批量删除沿用同一确认协议。
- 拖动必须在有项目和“全部任务”两种视图中都能跨列落库，目标列按任务所属项目解析，不允许仅改变前端位置。
- 任务的截止时间使用 `YYYY-MM-DDTHH:mm` 输入并按分钟展示；任务 dueAt 是日历只读投影的唯一来源，修改任务后必须失效日历查询。
- 任务、日历、仪表盘、工作台继续只读同一 `tasks` 表，不新增页面私有任务缓存。

## 2026-08-30 执行补充（当前有效约定）

- 单条任务在任意生命周期状态都可以通过右键“直接删除”，要求当前 `revision`、一次性确认上下文和数据库事务；批量永久删除仍仅允许已归档任务。
- “全部任务”看板的 `status:<status>` 合成目标会解析到任务所属项目的真实列，拖拽、菜单移动和日历投影都写回同一条 `tasks` 记录。
- 截止时间使用 `datetime-local`，默认精确到分钟；任务 `dueAt` 是日历只读投影的唯一来源。
## 2026-08-30 时间显示精度（当前有效约定）

- 看板卡片和共享任务时间使用本地化的“年-月-日 时:分”显示，不默认展示秒；编辑器继续使用 `datetime-local` 的分钟精度，数据库保存 UTC ISO 时间。

## 2026-08-30 最终基线：任务与日历同源

- 每个看板状态列都提供 `+` 和右键“新建任务”，创建请求直接写入目标状态；卡片右键可移动、归档或确认后硬删除。
- 看板、列表、日历、仪表盘和项目空间只读取统一 SQLite `tasks` 表。任务创建时间 `createdAt` 始终展示到分钟；没有截止时间时，日历以 `createdAt` 作为只读预览时间，避免任务在日历中消失。
- 拖动跨列必须提交目标状态并通过 revision/事务落库；刷新或切换项目筛选后仍从数据库重建视图，不保留页面私有副本。
